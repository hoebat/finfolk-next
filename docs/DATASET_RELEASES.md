# Runtime dataset releases

The map reads a pinned release under `https://datasets.finfolk.com.au/v1/map/releases/<id>/`.
`app/(atlas)/atlas/dataset-release.js` selects the release. It never follows a mutable
catalog while a user is downloading a region. Original surveys and generated runtime
copies remain in Git LFS; the dataset service streams materialized copies from an
allowlisted Git commit, without introducing another authoritative data store.

## Build

1. Materialize the LFS inputs registered in `datasets/inventory.json`. Bulk ocean
   acquisitions excluded by `.lfsconfig` can remain pointers; the static build
   checks registered raster, contour and regional context inputs before publishing.
   Register only reviewed numeric
   rasters through `python -m depth_explorer import-raster`; its datum and unit checks
   are mandatory. Preserve source metadata, masks, sign, grid alignment and licences.
2. Build the existing static artifact:
   `.venv/bin/python -m depth_explorer build-static --output .cache/dataset-site`.
   Then run `node scripts/build_explore_contours.mjs .cache/dataset-site` to build
   the Explore map's bounded vector tiles before packaging.
3. Package its data:
   `.venv/bin/python scripts/build_dataset_release.py --site .cache/dataset-site`.
   When extending the current coastal publication, add
   `--baseline datasets/runtime/releases/<current-id>` so the published native
   COGs, extra contour sources and exact vector archives remain available. The
   extension rejects changed vector sources and removal of existing numeric rasters.
4. Run `make generate`, `make check-generated`, `make test` and `make build`.
   The client release check loads real contours, saves a region, restarts offline,
   and rejects valid JSON whose hash differs from its manifest.
5. Commit and push `datasets/runtime/releases/<id>`, including its ordinary Git
   `manifest.json` and LFS `files/`. Verify that the remote commit and all LFS uploads
   exist before publishing a service release that refers to that commit.

The package copies generated bytes exactly. JSON and GeoJSON use deterministic HTTP
gzip; decompression reconstructs the original file and SHA-256. Numeric `.f32.gz`
chunks retain their existing compressed-byte contract and are not HTTP-decoded.
Explore vector tiles are grouped into reversible JSON/base64 archives by source and
zoom. The service verifies each archive, restores exact PBF bytes on request, and
keeps a bounded archive cache. The frontend no longer uploads duplicate vector tiles.
The release ID hashes the canonical manifest before its `id` field is added.
Packaging identical input is idempotent, and an existing release cannot be overwritten.

## Publish and roll back

In `hoebat/finfolk-datasets`, append a descriptor to `map-releases.json` with the
source repository, full pushed commit SHA, manifest path and manifest SHA-256.
Run `npm run setup`, `npm run build` and `npm test`. The service verifies the pinned
manifest and every committed LFS pointer without downloading bulk source surveys.
Publish the existing Sites project and check its live `/v1/map/current` endpoint,
catalog, contours, CORS headers and decoded SHA-256.

Only after the service is live, update the app's pinned release module, validate and
deploy the app through its existing Netlify workflow. Keep old service descriptors
and source commits available: rollback changes the app's release pin and redeploys.
Existing saved-region bytes remain intact and are keyed by release URL and file hash.

## Initial release coverage

The first release preserves 79 regions and 16 regions with published contours.
The initial release excluded numeric rasters: VCDem's whole-compilation review is incomplete;
the NSW mosaic's horizontal CRS evidence does not verify its vertical reference;
some WA BAG vertical references conflict with the publisher's index. Acquisition and
checksum verification alone do not establish those missing scientific contracts.

## Reviewed Pope’s Eye subset

The 20 January 2018 Deakin survey footprint now has a bounded AHD review in
`datasets/ocean/provenance/vcdem-popes-eye-review.json`. It registers 6,665 native
2.5 m cells inside a 5 m inset of that footprint and the acquired coastal band.
Every included value matches the original non-blended ASCII tile. Its float32
runtime chunks retain gaps and negate elevations exactly to express metres below
AHD; they do not provide tide-adjusted or chart-datum water depths.

The workbook and source-footprint geodatabase are retained as checksum-verified
archive fragments under `datasets/ocean/provenance/vcdem-package-review`. The review
records the source overlap analysis and inference from the publisher's non-blended
mosaic ordering. Source survey uncertainty is not a compiled-pixel accuracy promise.
Other VCDEM tiles remain unverified. The original full tile, full coastal COG and
footprint geometry remain available to reconstruct the prior representation.
